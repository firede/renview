# 产品与业务决策

- renview 定位：为 agent 主导开发场景优化人类审阅认知带宽的 diff review 工具，核心是人类看抽象是否合理而非逐行看实现。
- 前提假设：信任 agent 在各语言的基础实现能力，人类审阅聚焦抽象与业务是否相符，而非实现细节。
- 产品双能力：看变更（diff）与看代码（只读查看器）并重，共用同一简化/投影内核。
- 核心交互：基于静态程序化分析的语言感知 diff 投影 + 逐级披露，v1 不做 LLM 摘要。
- 主视图是简化 diff（伪代码级）：类型性质/技巧性质的语法从代码行中擦除，审阅者直接读简化后的逻辑（参考 rust-beautifier 的擦除规则）。
- 类型性变更的判定：同一 hunk 内简化后文本相同的 del/add 行对自动折叠为可见标记，点击展开看原始行；空行变更例外——不进折叠（展开无内容可审，折叠标记纯属干扰），以普通 del/add 空行呈现。
- 类型/结构体声明保留名字桩或成员名（数据形状变化保持可见，类型细节隐藏）。
- 声明分类管线服务于徽章、排序与行流内信号增强（签名 delta 高亮、折叠摘要成员级 delta），不产出独立的声明级单元卡片视图——信号融入行流就近呈现，行流仍是主视图，卡片流会把人拉回逐单元检查的传统 review。
- 披露阶梯按"常看程度"分层：业务信号（变更本身、词级 delta、成员级折叠摘要）零交互直接可见；行内被擦除的原文碎片 hover 浮层还原；折叠的原始全文与源码回退保留点击展开——折叠只适合绝大多数场景不看的内容（展开收起两次点击），常看信息不藏交互。
- 行内擦除可见化：简化视图中替换段带虚线下划线、删除点锚定到紧邻标识符加虚线下划线（前侧优先，均非标识符回落零宽 tick），hover 浮层还原被擦原文片段（op 即数据源）——hover 目标必须是真实文字，零宽空隙上的触发点会被忽略；擦除不能沉默，否则投影不可信。
- 简化器语言：TS/TSX、Rust、Go、GDScript、Python；各语言按语义安全线擦除类型与工程机制（Rust 的 ?/unwrap/clone、TS 的 ?.、Go 的 if-err-return 单行标记、Python 的 self/cast/TYPE_CHECKING 等）。
- Python 特有擦除：类方法的 self/cls 首参数（接收者是语言机制，函数体内 self. 保留——它区分实例状态与局部变量）、typing.cast、if TYPE_CHECKING 整块（单行标记）；装饰器保留（@dataclass/@property/@app.route 等是契约）。
- Python 纯数据类（body 无方法/嵌套类：dataclass、pydantic 模型、Enum、TypedDict）折叠为带成员名的单行摘要，装饰器名保留在摘要里。
- Go 的 `if err != nil { return }` 折叠为单行标记，非平凡返回值文本保留（fmt.Errorf 包装信息是业务定位信息）；带初始化语句的 err 判断不折叠（里面有真实调用）。
- 语言扩展：无 profile 的语言退回行级 diff；dogfood 验证优先用维护者不熟悉的语言（避免熟悉度掩盖投影问题）。
- v1 纯查看，不做评论、不做状态存储，用户发现问题后复制粘贴回 harness 用自然语言反馈。
- 主要入口是 agent harness 内 slash 命令 / skill 触发 CLI，CLI 参数语义贴合 git diff。
- CLI 无参默认展示 working tree vs HEAD 的变更（贴合 agent harness 的 diff 视图语义）。
- 默认 diff 必须包含 untracked 新文件（agent 常新建文件，漏掉会形成审阅盲区）。
- 信任原则：折叠而非删除，每个折叠处可见隐藏了什么并可展开，任意层级一键回到原始 diff。
- 解析失败或超大文件降级为行级 diff，且降级状态对用户可见。
- 无简化规则（no-profile）不算降级、不在界面呈现原因（用户无从行动）；解析失败/文件过大等真实降级仍保持可见。
- body 变更的"摘要"是结构化枚举（哪个分支变了、新增了什么调用），不是自然语言摘要。
- 实现摘要注释行：body 变更单元触及 ≥2 条顶层语句时，在该单元范围内首行之前插一行注释色摘要（决策点/调用的简化文本枚举，超 3 条截断显示总数）——单条变更在行流中自明，加摘要是重复噪音；多语句/scattered 变更的聚合索引才有增量价值。
- 注释变更折叠为"注释变更"低优先级单元：可见、可展开，但不打断主审阅流程。
- 侧栏排序：签名变更（summary.signature > 0）的文件排最前，组内保持 git diff 原顺序——审阅顺序物理化为"先看契约，再看实现"。
- 目标规模按单 PR 级 diff 设计，初期不做 monorepo 性能设计。
- worktree 支持、已看标记、agent 化 review 能力均为后期事项。
- 只读查看器：完整文件渲染为伪代码级简化视图——不承诺合法语法与完整语义，是促进理解的投影，可随时切回源码对照（类 markdown 编辑/预览关系）。
- 查看器目标：屏蔽类型推导/工程化/内存管理等语言复杂度，让人聚焦业务建模与抽象合理性；既服务审阅，也服务日常理解 agent 写的代码。
- hover 细节分两层：v1 展示被擦除的原文片段（行内擦除点降权标记 + hover 浮层还原）；参数类型结构等语义级 hover 依赖 LSP 增强层，后置。
- 词级行内 diff 高亮只加在简化视图：配对的 del/add 行按词求差并着强调色（签名增参、规则条伴变化零交互可读）；原始 diff 视图是审计回退，不加增强。
- 类型/形状折叠的摘要升级为成员级定位（如 `Point：y（类型/格式变更）`）——折叠的是同成员的类型/格式细节变化（成员增减简化文本不同、本就可见），摘要须说明是哪个声明的哪些成员；无法关联到类型声明或定位不到成员时回落原"折叠 N 行"摘要。
- hunk 外上下文不在 diff 视图内展开，由跳转查看器完整文件视图承接。
- 领域投影（如 JSX 内 tailwind 原子类 → 元素 hover 样式预览）为远期方向，非 v1 承诺。
- 发布节奏：公开发布由维护者显式打 tag（npm version + git push --follow-tags）触发 release.yml，dogfood 认可前不发 tag；分发工程（安装脚本 / npm CDN / upgrade）已落地。
- 更新检测默认开启：启动时缓存命中才打印一行提示、后台异步刷新（24h 间隔），升级只能由用户显式 `renview upgrade` 触发——不自动升级、不阻塞审阅；`update_check = false` 或 `RENVIEW_DISABLE_UPDATE_CHECK` 可关闭。
- 查看器 v1 固定展示 working tree 版本（与 diff 默认语义一致），rev 切换后置。
- 擦除语义安全线：以"是否影响业务抽象理解"而非"是否影响运行时语义"划线——内存/指针/封解包等语言机制（如 Rust 的 &/&mut、数字后缀）信任 agent 做对、可以擦除；使用者聚焦业务模型是否与现实相符、大体如何工作。
- 查看器与 diff 均默认展示简化视图；投影态通过工具栏"简化/源码"激活态常驻可见（投影不伪装成源码）。
- 折叠的视觉语义：折叠态摘要用注释同色降权抗干扰；展开即进入审视，展开内容带完整语法高亮（逐级披露的一部分）。diff 与查看器的折叠共用同一行式形态（整行可点、gutter 留空、箭头 + 摘要），不另设 chip 按钮形态。
- 快捷键约定：`S` 在简化与源码/原始 diff 间切换（无修饰键、输入框聚焦时豁免）；后续快捷键沿用"单字母、无修饰、输入框豁免"。
- 控件按作用域归位：视图级控件（单列/双列）归文件工具条（仅原始 diff 视图可见），不置顶栏；投影态通过文件工具条底色可一眼识别。
- 简化与原始 diff 两视图的行高、行号几何与字体对齐，切换无位移。
- 无任何 diff 变更时，首次打开默认进入浏览模式（审阅视图无内容可看）。
- 侧栏按场景分化：浏览模式为目录树（目录优先、单子目录链压缩为 a/b、过滤时退回平铺列表）；变更模式保持变更文件平铺列表（变更集本就稀疏）。
- 查看器投影为分层压缩：行内 token 擦除之外，顶层 imports 连续段与类型级声明（interface/type/enum/struct/trait/use）折叠为单行摘要（可展开看源码原文）；被抹空的行与连续空行不占行。
- 折叠摘要保留成员/变体名（领域词汇即数据形状），超过 6 个截断并显示总数。
- imports 在查看器折叠为单行标记；diff 视图中 import 变更保持可见（依赖变化是审阅信号）。
- body 工程机制擦除 v1：Rust 的 ?/unwrap/clone/into/to_string/to_owned（零参）；TS 的 ?. → .；async/await 保留（挂起点影响流程理解）；日志/指标调用不做孤立单行折叠（无纵向收益）。
- 函数体设计基线：body 视图 = 扫读叙述（步骤 + 决策点），起疑时下钻（hover/展开/源码）；不做常驻的 verification tooling（参数追踪/作用域/调用来源标注），避免把人拉回逐行验证。
- 配置是手改的 TOML 文件（无设置 UI），保存后窗口聚焦即生效、无需重启 CLI——复用前端已有的 focus 刷新模型，不引入文件 watch。
- 配置容错红线：语法/类型错误回退默认值并在终端警告，配置问题永不阻塞审阅；未知键静默忽略（新旧版本二进制互读配置不报错）。
- font_size 只作用于代码阅读区（diff/简化视图/查看器），行高/行号/行号栏宽随字号等比联动（投影会议等大字号场景不拥挤），UI 镀铬不随字号缩放。
- 查看器折叠行的 gutter 不标行号区间：折叠语义由箭头与摘要承担，区间可由上下文行号推断；区间文本（如 21–23）在可配大字号下必然拥挤。行号字号跟随代码字号（小 1px 降权），不各自固定。
- 多语言 v1：语言集 zh-CN + en，配置项 `language`；未设置时 CLI 启动阶段按环境检测（LC_ALL > LC_MESSAGES > LANG > OS locale），BCP 47 根语言匹配（zh-TW 归 zh-CN），最终回落英文——英文是非中文用户的最大公约数，自动检测保住零配置体验。
- 语言切换复用配置流（保存后窗口聚焦生效），不提供界面内切换入口——语言是配置而非会话状态，与"配置是手改 TOML、无设置 UI"一致。
- 文案按目标语言原生习惯重写命名而非逐字对译（单列/双列 → Unified/Split，`import × 3` → `3 imports`），语言文件按 BCP 47 标签命名——机械翻译腔会损害工具的专业可信度。
- 伪代码标记（`if err: return`、`if TYPE_CHECKING: …`）两语言共用、不翻译——它们锚定源码关键字，翻译会误导与源码的对照。
- 本地化范围 = CLI 输出 + 配置警告 + API 错误 + 分析层摘要串 + Web 界面；scripts/ 开发脚本输出不本地化（受众只有维护者）。
