# 仓库整体审查与优化（2026-09-05）

本次从 CLI → Git 数据 → CST 投影/简化 → HTTP → React 阅读界面的主路径审视架构，并检查配置、更新、构建和演示样例的边界。结论是保留现有模块体系，优先修复资源生命周期、审阅范围、异步状态与计算复杂度；这些问题直接影响长期使用与审阅可信度，收益大于大规模拆文件或更换依赖。

## 架构判断

- `src/analysis/langs/` 将语言规则与投影引擎分开，`simplify`、`view` 与原始 diff 提供渐进披露，核心边界合理；此次保留规则与显示语义。
- 源码解析后由多个消费者共用 CST 是正确方向，但资源所有权此前依赖 tree-sitter 最终回收器；回收时机不由请求生命周期控制。
- Git 数据与展示数据之间需要统一来源，原实现无条件拼入未跟踪文件，使暂存区与提交区间混入工作区草稿。
- React 组件自行维护相似的 fetch/effect 状态，遗漏取消、乱序保护与错误反馈；统一这个边界比按行数拆分组件更有价值。
- 两处成本与有效输入不成比例：每行扫描全部擦除操作，以及为 diff 最大行号填充空白文本；可直接改进，无需先引入缓存或全仓索引。
- 配置、升级与多平台分发已有独立模块和测试，当前证据不足以支持本轮替换技术栈。

## 性能与验证

本机 Bun 1.4.1 / macOS arm64 的合成样本：重复 `const n: number = 1;`，每行擦除 `: number`，比较优化前后的 `applySimplify`，包含输出文本与擦除记录的完整相等检查。

| 行数 / 擦除数 | 优化前 | 优化后 |
| --- | ---: | ---: |
| 5,000 | 32.32 ms | 3.28 ms |
| 10,000 | 118.79 ms | 4.87 ms |
| 20,000 | 403.05 ms | 9.54 ms |

这是单次本地合成基准，说明消除重复扫描的收益，不代表端到端延迟或所有仓库的固定加速比；另有 500 组固定种子的随机样本对照旧实现，输出完全相同。

- 基线 153 项测试；完成后 `bun run test` 为 **167 项通过、0 失败**，`bun run typecheck` 通过。
- 高亮回归覆盖百万行文件尾部的两行变更、多 hunk 和新旧行号偏移。
- 应用内浏览器验证快速切换文件、服务停止时显示错误、服务恢复后点击重试、简化与原始 diff 切换及高亮布局。
- `bun run scripts/build.ts --host` 通过；本机单文件二进制的版本、配置/文件列表/diff 接口、连续 20 次文件投影与大纲读取、400/404 状态冒烟通过。
- 本轮没有执行跨平台发布矩阵、完整外部仓库语料回归或长期内存压测；不据此宣称所有语言和所有 Git 参数已全面兼容。

## 后续值得单独处理

1. **Git 参数与投影来源的契约。** `src/git.ts` 的 `resolveSides` 仍通过忽略 flag、收集非 flag 字符串推导 revision，未完整处理 `-R`、带独立参数值的选项及无 `--` 的路径；应先明确支持范围，再用真实 Git 输出做表驱动回归，无法可靠推导时退回原始 diff。
2. **语言感知的等价判断。** `src/analysis/project.ts` 的空白归一化会抹平字符串内部连续空格，可能把业务字符串变化误归为声明外变更；应基于 CST 保留字面量内容，并以多语言语料验证格式降噪，避免简单正则修补。
3. **文件输入边界与负载控制。** `src/server.ts` 的路径检查是词法检查，未校验符号链接的真实目标；大文件仍先读取全文，diff 文件分析仍一次并发启动。后续应明确链接读取策略、读取上限及并发预算，再验证大仓库和特殊文件，不直接扩张为全仓索引。

这些是现有代码中可定位的后续工作，未作为本轮新增产品承诺。
